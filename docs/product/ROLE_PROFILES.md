# Initial Role Profiles

The four approved roles use a curated, versioned baseline. Category weights feed the role-skill component of the Interview Preparation Readiness Score and total 1.00 per role.

Resume content can specialize questions within these categories. It cannot introduce a new readiness category during a live session.

## Software Engineer / Developer

Domain: General Software Engineering.

| Category | Weight | Initial skills |
|---|---:|---|
| Programming Fundamentals | 20% | Control flow, functions, data types, error handling, complexity basics |
| Data Structures and Algorithms | 25% | Arrays/strings, linked lists, stacks/queues, trees/graphs, sorting/searching, time/space complexity |
| OOP and Design | 15% | Encapsulation, inheritance/composition, polymorphism, SOLID basics |
| CS Fundamentals | 20% | DBMS, operating systems, computer networks |
| Engineering Practices | 20% | Git, testing, debugging, code quality, problem solving |

The baseline is language-agnostic. A confirmed resume may cause a question to use the user's listed language.

## Backend Developer

Domain: Web Backend and API Development.

| Category | Weight | Initial skills |
|---|---:|---|
| Server Fundamentals | 20% | Runtime/concurrency, request lifecycle, configuration, error handling |
| HTTP and API Design | 25% | HTTP semantics, REST, validation, status/errors, versioning |

The role is technology-neutral; Node/Express-specific questions are used only when selected by resume/context or by an explicitly future profile revision.

## Profile rules

- IDs and category/skill IDs are stable machine identifiers.
- Display names may improve without changing IDs.
- Weight or taxonomy changes require a new role-profile version.
- Every interview stores the role-profile version used.
- AI output may select only allowlisted category/skill IDs.
- Initial questions cover categories; deep evidence targets individual skills.
